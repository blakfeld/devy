# Proposal

## Why

`devy init` writes an empty starter config, while the useful draft hides behind `--ai`. The Claude-drafted config is what nearly every user wants from `init`. `claude` is an accepted runtime dependency of `init`, so there is no reason to make users discover a flag to get it.

## What Changes

- **BREAKING** `devy init` with no flags runs the project scan and drafts `devy.yml` with Claude, which is what `devy init --ai` did before.
- **BREAKING** The `--ai` flag is removed. Passing it is a usage error (exit 2).
- `devy init` requires the `claude` CLI. When it is missing or fails, `init` exits 1, writes nothing and suggests `devy init --detect`. There is no silent fallback.
- `--detect` stays as the explicit offline mode, and never looks for `claude`.
- `--show-context` no longer needs `--ai`. It conflicts with `--detect`, which sends nothing.
- The empty starter config is no longer a mode of its own. `--detect` writes it, with its header, when nothing is detected.
- The AI header becomes `# Generated by devy init (<model>) — AI-generated, review before committing`.

## Capabilities

### New Capabilities
None.

### Modified Capabilities
- `project-config`: the Init command default changes, `--ai` is removed, and the AI init and Detected init wording changes to match.
- `ai-assist`: scenarios name `devy init` instead of `devy init --ai`, and `init --detect` is the init mode that must never run `claude`.

## Impact

- **Code:**
  - `src/cli.rs` — `Init` flags.
  - `src/commands/init.rs` — mode dispatch. `run_with` injects the client lookup so tests never reach a real `claude`.
- **Tests:**
  - The plain-`init` integration tests now use a fake `claude` script on PATH (Unix) or an empty PATH.
  - This adds the first end-to-end coverage of the real subprocess transport: arguments, working directory, stdin, and error reporting.
- **Docs:** README Quick start, Requirements, `devy init` and AI features.
- **Users:** scripts that relied on `devy init` writing an empty config offline must switch to `devy init --detect`.
