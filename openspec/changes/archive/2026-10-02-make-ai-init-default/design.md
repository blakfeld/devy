# Design

## Context

- `init` has three modes: plain (empty starter), `--detect` and `--ai`.
- `--ai` already requires `claude` and exits 1 when it is missing or fails.
- `claude` is an accepted runtime dependency of `devy init`.

## Goals / Non-Goals

**Goals:**
- `devy init` gives the best draft by default.
- No test can run a real `claude`, even on a developer machine where it is installed.

**Non-Goals:**
- Falling back to `--detect` when `claude` is unavailable. A silent fallback would hide a missing dependency and produce a weaker config than the user asked for. The error names `--detect` instead.
- Keeping a flag for the empty starter config. `--detect` in an empty directory produces it.

## Decisions

### D1. `Mode` is `Ai { show_context }` (the default) or `Detect`
The CLI maps `--detect` to `Detect` and everything else to `Ai`. clap rejects `--detect --show-context` (`conflicts_with`) and, since `--ai` no longer exists, `--ai`. Both are exit 2.

### D2. Injected client lookup
`init::run` delegates to `run_with(mode, force, path, client: impl FnOnce() -> Result<Client>)`, passing `Client::from_env`. Unit tests pass a fake transport, a missing-claude error, or a closure that panics if called. The panicking closure proves that `--detect` and the existing-file check never look for `claude`.

### D3. Fake `claude` for integration tests
On Unix, `tests/cli.rs` writes an executable `claude` shell script into a temp bin dir and sets `PATH` to only that dir. The script:
- records its arguments, working directory and stdin
- prints a canned `--output-format json` result

This is the first test of `CliTransport` end to end: process spawn, stdin piping, the empty working directory, the sandboxing flags and error parsing. Windows runs the missing-claude and `--detect` cases, which use an empty `PATH`. A `.cmd` fake would also work there, but it is left out to keep the fixture simple.

### D4. Header without the flag
`# Generated by devy init (<model>) — AI-generated, review before committing`. `--detect` keeps `# Generated by devy init --detect — review before committing`, which also tells the reader how to reproduce it.

## Risks / Trade-offs

- **[Breaking for offline scripts]** → `devy init` in CI or offline now fails without `claude`. The error suggests `--detect`, and the README and proposal call it out.
- **[Content leaves the machine by default]** → It still happens only when the user runs `devy init`, the command that is documented as AI-powered, and `--show-context` previews it. Redaction is unchanged.
